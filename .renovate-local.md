# Renovate merge guidance

Read by the local Renovate merge skill. The public renovate-eval action and
skill do not read this file.

## What changes what runs

Clayton runs go-unifi-mcp from claytono/infra's flake, which pins it to a commit
(`flake.lock`, and `kubernetes/semaphore/nix-flake.lock` for Semaphore), so a
merge here does not change his copy until infra moves that pin. Other people get
`main` straight away: every merge publishes the
`ghcr.io/claytono/go-unifi-mcp:edge` image, and
`nix run github:claytono/go-unifi-mcp` builds `main`. The `:latest` image is the
latest release's binary on the current `Dockerfile`; a merge that changes
`Dockerfile` rebuilds it, but does not change the program in it. Releases and
Homebrew are separate and manual (RELEASE.md).

An update changes the program if it touches `go.mod`, `go.sum`, `cmd/`,
`internal/`, `flake.lock`, or the part of `flake.nix` that builds the package
(`goFor` and the `go-unifi-mcp` package with its `vendorHash`). Check those
before merging, from the PR, as below. A `Dockerfile` update only changes the
images: CI's `docker` job builds it, and its `main` runs must pass after the
merge, as below. Every other update only needs CI, including GitHub Actions,
pre-commit hooks, `.go-unifi-version` (the go-unifi release `task sync-go-unifi`
copies code from; nothing changes until that runs) and `flake.nix` changes to
the development shell's tools, such as go-test-coverage, mcp-publisher or
mcp-cli.

## Checking it, before merging

Nothing is deployed: build the PR and smoke-test it against the UDMP.

1. In a worktree at the PR head, build the program the way Nix users get it:

   ```bash
   nix build --no-link --print-out-paths .
   ```

2. Make one read-only call through the built binary. Copy the `unifi` server
   from claytono/infra's `.mcp_servers.json` into a config file in the run
   directory, keeping its `UNIFI_TOOL_MODE=eager` (in the default lazy mode
   `list_device` is not a tool), with its `command` set to `bin/go-unifi-mcp`
   under the path `nix build` printed, and run:

   ```bash
   MCP_NO_DAEMON=1 mcp-cli -c CONFIG call unifi/list_device '{}'
   ```

   `MCP_NO_DAEMON=1` keeps mcp-cli from starting its background daemon, whose
   command line would carry the API key. The call must exit 0 and list the
   controller's devices.

   The config reads `UNIFI_API_KEY` from the environment. It comes from
   claytono/infra's direnv secrets (`.secrets.tmpl`, decrypted from
   `.secrets.age` with no 1Password prompt), so the check runs from a session
   started in an infra checkout. Before showing the table, confirm it is set
   without printing it (`[ -n "$UNIFI_API_KEY" ]`); if it is not, show the PR as
   Blocked.

## After merging

Merging to `main` publishes the images; nothing else to deploy. Its `main` runs,
including Edge and, for a `Dockerfile` change, Rebuild Latest Docker Image, must
pass. The `:edge` image must have the merge commit as its
`org.opencontainers.image.revision` label, read with `skopeo inspect`, and so
must `:latest` after a `Dockerfile` change, where the label identifies the image
build rather than the program in it.
